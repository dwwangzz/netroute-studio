# NetRoute Studio 开发收尾清单

每次完成代码、界面、安装程序或发布流程修改后，按以下顺序检查。项目级 `AGENTS.md` 要求后续 Codex 会话遵循本清单。

## 1. 检查工作区

```powershell
git status --short
git diff --check
```

- 保留用户已有修改和不属于当前任务的提交。
- 不使用会丢失工作区内容的 Git 命令。

## 2. 同步应用版本

功能或修复完成后递增补丁版本，并同步以下位置：

- `src/NetRouteStudio.App/NetRouteStudio.App.csproj`
  - `Version`
  - `AssemblyVersion`
  - `FileVersion`
- `installer/NetRouteStudio.iss`
  - `MyAppVersion`
  - `NumericVersion`
- `.github/workflows/release.yml` 中的手动发布示例版本。
- `README.md` 中的发布目录、Inno Setup 参数、安装包名称、当前版本和标签示例。
- `CHANGELOG.md` 顶部新增对应版本和日期。

版本规则：

- 常规修复或小功能：递增 `X.Y.Z` 中的 `Z`。
- 有兼容性影响或较大功能集合：先向用户确认是否递增次版本或主版本。
- Git 标签使用 `vX.Y.Z`，程序集数值版本使用 `X.Y.Z.0`。

## 3. 构建与稳定测试

```powershell
dotnet build NetRouteStudio.sln --no-restore --configuration Release --maxcpucount:1
dotnet test NetRouteStudio.sln --no-build --no-restore --configuration Release --maxcpucount:1 --filter "Category!=Integration"
```

若依赖尚未恢复，先执行：

```powershell
dotnet restore NetRouteStudio.sln --configfile NuGet.Config --disable-parallel
```

真实网络集成测试依赖本机网卡、路由、DNS、IPv6 和公网环境，不作为日常稳定测试的阻断条件。

## 4. 安装与发布修改检查

涉及安装包时额外检查：

- `installer/NetRouteStudio.iss` 能找到仓库内的中文语言文件和应用图标。
- 安装完成启动使用 Windows Shell，能够正常触发管理员权限请求。
- `.github/workflows/release.yml` 中的发布版本、输出文件和 SHA-256 步骤保持一致。
- 本机未安装 Inno Setup 时，明确说明最终安装 EXE 需要 GitHub Runner 验证。

## 5. 交付说明

最终回复至少包含：

- 完成的主要修改。
- 当前应用版本。
- Release 构建是否通过及警告/错误数量。
- 稳定测试通过、失败和跳过数量。
- 是否完成安装包实机验证。
- 修改是否已提交、打标签或推送。

除非用户明确要求，否则不要自动执行 Git 提交、创建标签或推送远端。需要提交时，提交说明必须使用中文。
